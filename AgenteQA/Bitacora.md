- 2026-08-29: **validacion final del MVP** contra un sitio real de produccion (armoniachile.cl, e-commerce), pedida por Diego para confirmar que el agente no se desvia de un analisis manual independiente (hecho con WebFetch antes de correr el agente).
  - Comparacion: el analisis manual identifico e-commerce con categorias, carrito, login/registro, newsletter, checkout Transbank, WhatsApp. El agente, con un alcance acotado explicitamente (sin login/carrito/checkout, sin compras/suscripciones reales), genero un plan de 6 casos (3 ui + 3 endpoint) cubriendo exactamente carga de home + 2 categorias mencionadas — **se alineo bien y respeto las restricciones de seguridad pedidas**, no se desvio a nada fuera del alcance.
  - **Bug real encontrado**: `httpx.get` con el User-Agent default de python-httpx (`python-httpx/x.x`) fue rechazado por el WAF/anti-bot del sitio (`RemoteProtocolError: Server disconnected`), silenciosamente devolviendo `None` en `page_inspector.py`. Fix: `REQUEST_HEADERS` con un User-Agent de Chrome real, aplicado al `httpx.get` de `inspect_page`.
  - **Segundo bug real**: con 8 paginas de categoria a inspeccionar, el `page_snapshot` combinado llego a >12.000 tokens en un solo request — exploto tanto el limite diario (200k TPD) como el limite por-minuto (8000 TPM) de dos cuentas gratis de Groq distintas. Fix: `MAX_SNAPSHOT_CHARS` (4000 chars) en `format_snapshots()`, trunca con aviso en vez de fallar el request entero.
  - **Tercer hallazgo (parcialmente arreglado)**: `assert_visible` fallaba en links de menu que SI existen y son visibles (confirmado con screenshot) — causa: el mismo href se repite en menu desktop + menu mobile oculto + footer/sitemap (patron comun en WordPress/WooCommerce), y Playwright evalua la visibilidad del PRIMER match en el DOM, que resulto ser el oculto. Fix: `page_inspector.py` ahora trackea landmarks (`nav`/`header`/`footer`) y prefija los elementos (`[header] <a href=...>`), y `PLAN_SYSTEM_PROMPT` instruye a preferir selectores acotados (`header a[href=...]`) cuando hay ambiguedad. Resultado: funciono para la pagina de inicio (TC-01 paso), pero **sigue fallando al navegar a la pagina de categoria** — el menu mobile oculto vive DENTRO del mismo `<header>` que el desktop, nuestra heuristica de landmark no distingue "visible" de "oculto" dentro del mismo contenedor. Limitacion real documentada: resolverlo del todo necesitaria chequear visibilidad computada con un browser real en el pre-vuelo, no solo HTML estatico.
  - **Reportado a Sebastian (no tocado)**: `execution/endpoint_runner.py` tiene su propio `httpx.AsyncClient` sin el fix de User-Agent — los tests tipo "endpoint" contra este mismo sitio fallaron con el mismo `RemoteProtocolError` que ya arreglamos en `page_inspector.py`. Mismo bug, replicado en otro archivo por no compartir cliente HTTP configurado.
  - Cobertura tras los fixes: 80 tests, 98.93%.
